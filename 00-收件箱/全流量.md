mpstorage
独立可执行程序，业务挂在  闭源收包框架   上
### A. 启动与进程编排（业务）

| 项    | 内容                                                                                 |
| ---- | ---------------------------------------------------------------------------------- |
| 关键文件 | `realeye/source/main.c`                                                            |
| 职责   | 读 `-c` 配置、清临时目录、加载规则、启动 DPDK 框架、拉统计线程、定时热更规则                                       |
| 输入   | 命令行 `-c restore.ini`；规则文件 `/zrtx/para/realeye/rules/rule_encode_key.php`           |
| 输出   | 调用 `main_dpdk(...)` 把 4 个回调交给框架；另写流量统计到 `/u2/workdir/1001/flow/`、`/var/detectlog/` |

`flow_init()` 在 `main` 里被注释掉了，启动时不会跑。

### B. 业务回调：把框架解析结果写成日志（核心业务）

|项|内容|
|---|---|
|关键文件|`realeye/source/restore.c`、`restore.h`|
|职责|框架解析完一条流/告警后回调这里；拼 JSON，写磁盘|
|输入|框架传入的 `node_stat`（五元组、包数字节数）、`flowid`、`DATA_INFO`（HTTP/告警/协议字段）|
|输出|访问日志、告警日志（路径来自框架配置 `g_port_cfg__access_log_file_path` / `g_port_cfg__alert_log_file_path`）；黑名单日志写 `/dev/shm/blackdb`|

四个注册函数（在 `main()` 里交给 `main_dpdk`）：

1. `restore_access_log_callback`：会话/访问日志 JSON
2. `restore_monitor_log_callback`：告警 JSON（命中 Snort 规则时带 payload、规则 ID）
3. `user_define_writepcap_callback`：当前直接 `return`，全流量 PCAP 落盘后本目录不再搬文件
4. `file_data_second_process`：文件还原二次处理，协议分支被 `#if 0` 关掉，等于原样交回框架

### C. 规则表（业务）

| 项    | 内容                                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------------- |
| 关键文件 | `realeye/source/detect.c`、`detect.h`                                                                        |
| 职责   | 解密规则文件，建成哈希表；告警日志里用 SID 查分类名、等级                                                                             |
| 输入   | `/zrtx/center_data/data/rule_files/local_mrule.php`（`combine_rule_queue_init` → `SigLoadCombineSignatures`） |
| 输出   | 内存表 `g_table_qr_fr`；`combine_rule_check_sid_qr_fr_rule()` 给 `restore.c` 填 `alert.signature`                 |

### D. 协议名、资产方向（业务，但和 Makefile 不同步）

|项|内容|
|---|---|
|关键文件|`map_protocol.c`、`discove-assets*.c`|
|职责|`map_found_queue`：app_type → 应用名；`AssetsCheckPacketAssetRole`：源/目的 IP 是否内网，打 `asset_role`|
|输入|`/zrtx/para/realeye/protocol` 目录；包的 IP|
|输出|告警 JSON 里的 `app_name`、`asset_role`|

`restore.c` 确实调用了这些函数。但仓库里现成的 `Makefile` 没有编译这些 `.c`。`automake.sh` 会 `qmake -project` 再拼工程，重新生成后才可能编进去。阅读时把它们当业务代码，构建以 `automake.sh` 为准。

### E. 公共工具（本仓库自己的）

|文件|实际用途|
|---|---|
|`inifile.c`|读 ini（`zw_GetIniKeyString`），`main` 用来读 DPDK 口数、PCI|
|`debug.c`|打日志到 `/u2/workdir/mpstorage.txt`|
|`str_authcode.c` + `nmd5.c` + `base64_decode.c`|`DecryptFileToMem` 解密规则|
|`ipcalc.c` / `avltree.c`|被资产相关头文件使用；待确认是否进当前链接|

### F. 第三方 / 闭源（不要当业务读）

|位置|是什么|
|---|---|
|`include/frame/` + `lib/frame`（构建时）|收包、解码、存 PCAP、调回调。头文件是「SDK 说明书」|
|`include/dpdk/`、`lib/dpdk/`、`dpdk.sh`|Intel DPDK，从 `/usr/local/dpdk` 拷来|
|`include/hs_x86/`、`include/hs_uos/`|Hyperscan 正则引擎头文件|
|`realeye/source/cJSON.c`|开源 JSON 库（规则解析）|
|`include/marex/`、`include/decode/`、`include/analyze/`、`include/xrt/`|框架周边头文件；本 app 的 `Makefile` 未直接链对应 `.c`|

### G. 构建脚本

- `realeye/sh/automake.sh`：真正生成 `.pro` / `Makefile` 的脚本
- `realeye/sh/c.pro`：程序名、优化级别、库路径定制
- `lib/temple.pro*`：DPDK 链接模板（不同网卡型号有副本）
