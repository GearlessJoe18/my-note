# 权限获取与维持学习记录

日期：2026-08-04
主题：权限获取与维持类告警总结

## 一句话结论

权限获取与维持的本质是：攻击者在获得初始入口后，通过 WebShell、内网代理、隧道转发、提权工具、远控木马或持久化通道，把一次性的漏洞利用或登录成功转化为可反复访问、可持续控制、可进入内网、可提升权限的长期攻击能力。

## 权限获取与维持是什么

权限获取与维持通常位于攻击链的中后期。

如果说信息探测是在找入口，漏洞攻击是在打入口，命令与控制是在执行命令和回连，那么权限获取与维持就是攻击者想办法“站稳脚跟”。

常见目标包括：

- 获得 Web 服务器命令执行能力
- 通过 WebShell 长期控制网站服务器
- 建立代理或隧道进入内网
- 绕过边界访问限制
- 提升当前权限
- 保持长期访问入口
- 把受害主机变成跳板
- 为横向移动、数据访问和进一步控制做准备

## 与前面几类告警的区别

| 阶段 | 主要目的 | 常见表现 |
|---|---|---|
| 信息探测 | 发现资产、端口、目录、服务和弱口令入口 | 扫描、爬虫、目录枚举、暴破 |
| 漏洞攻击 | 利用缺陷造成读取、写入、执行或绕过 | 注入、文件读取、命令执行、未授权访问 |
| 命令与控制 | 对主机下发命令或建立远控回连 | CobaltStrike、反弹 Shell、系统命令执行 |
| 权限获取与维持 | 保持访问、提权、代理转发、进入内网 | WebShell、隧道、Socks、端口转发、提权工具 |

权限获取与维持类告警通常比普通扫描告警严重，因为它往往说明攻击者不只是“试探”，而是在建立持续访问能力。

## 这些告警的共同点

共同点可以总结为：

- 都与持续控制、代理转发、权限提升或后渗透通道有关
- 很多行为发生在漏洞利用成功、后台被攻破或 WebShell 落地之后
- WebShell 类告警说明攻击者可能已经具备 Web 服务器命令执行能力
- 隧道和代理类告警说明攻击者可能正在借受害主机进入内网
- 提权工具类告警说明攻击者不满足于当前权限，正在尝试获得更高权限
- 单条告警仍需结合文件、进程、网络、请求和日志判断是否成功

## 攻击具体行为总结

权限获取与维持类行为可以概括为：

> 攻击者通过文件上传、漏洞利用、弱口令、后台权限或 WebShell 落地，在目标主机上建立可重复访问的控制入口，并通过代理、隧道、端口转发或提权工具扩大控制范围，使自己能够长期访问服务器、穿透边界进入内网，或获得更高系统权限。

## 行为分类

| 类型 | 代表告警 | 具体行为 | 可能影响 |
|---|---|---|---|
| WebShell 连接 | 通用 WebShell 连接、加密 WebShell 连接 | 攻击者通过 HTTP/HTTPS 请求连接服务器上的 WebShell 文件 | 长期控制 Web 服务器、执行命令、读写文件 |
| WebShell 命令执行 | WebShell 命令执行 | 通过 WebShell 下发系统命令 | 查看系统信息、下载木马、读写文件、创建账号 |
| WebShell 管理工具 | 中国蚁剑、中国菜刀、冰蝎、哥斯拉、weevly | 使用专门客户端管理 WebShell | 文件管理、数据库操作、命令执行、代理转发 |
| 内网代理工具 | reGeorg、EarthWorm、pystinger、Tunna、SPP、NPS、Lanproxy | 在受害主机上建立代理或转发通道 | 进入内网、访问内网服务、横向移动 |
| 端口转发 | Fpipe、reDuh、通用代理转发 | 将外部连接转发到内网目标端口 | 绕过边界访问限制，访问内部数据库、RDP、Web 等服务 |
| 通信隧道 | BadTunnel、UDP 隧道、ICMP 隧道、HTTP 隧道、Socks5 隧道 | 使用非常规或封装协议传输流量 | 绕过防火墙、隐藏 C2 或内网访问流量 |
| 提权工具 | Linux 提权工具利用 | 利用系统漏洞、错误配置或提权脚本提升权限 | 从普通用户提升到 root 或更高权限 |

## WebShell 类告警怎么看

WebShell 是攻击者放在 Web 目录中的后门脚本。攻击者通过访问这个脚本，向服务器下发命令或操作文件。

常见 WebShell 相关告警包括：

- 通用 WebShell 连接
- WebShell 命令执行
- 加密 WebShell 连接
- Behinder 冰蝎木马
- Godzilla 哥斯拉木马
- 中国蚁剑
- 中国菜刀
- weevly WebShell 管理工具

### WebShell 怎么完成攻击

典型过程：

```text
漏洞利用 / 弱口令 / 后台登录 / 文件上传
-> 上传或写入 WebShell 文件
-> 攻击者访问 WebShell 地址
-> WebShell 在服务器端执行命令或文件操作
-> 攻击者持续控制 Web 服务器
```

### WebShell 怎么判断成功

可以判断成功或高度疑似成功的证据包括：

- Web 目录出现异常脚本文件
- 文件名、路径、内容、修改时间异常
- 访问某个脚本后出现命令执行行为
- Web 服务进程启动 `cmd.exe`、`powershell.exe`、`sh`、`bash` 等命令解释器
- 请求体中出现加密参数、长参数、固定密钥或 WebShell 工具特征
- 同一 URL 被反复访问并产生文件操作、命令执行、数据库访问
- 服务器出现可疑文件上传、下载、压缩、删除行为
- WebShell 连接后出现隧道、代理或木马落地行为

### WebShell 可能获得什么

攻击者可能获得：

- Web 目录文件读写能力
- 当前 Web 服务用户权限
- 系统命令执行能力
- 网站源码、配置文件、日志文件
- 数据库连接信息、账号密码、密钥、Token
- 上传下载文件能力
- 继续投递木马、代理或提权工具的能力

不确定内容：

- 只有 WebShell 连接告警，不能确认具体执行了哪些命令
- 只有工具特征，不能确认 WebShell 文件仍然存在
- 没有 Web 日志和主机日志时，不能确认文件落地路径和影响范围

## 隧道与代理类告警怎么看

隧道和代理工具的核心目的是：让攻击者通过受害主机访问原本无法直接访问的内网资源。

常见告警包括：

- BadTunnel 隧道
- reGeorg 代理转发工具
- EarthWorm 代理转发工具
- UDP 隧道
- Socks5 隧道
- 通用通信隧道
- Tunna 代理转发工具
- pystinger 内网代理工具
- SPP 代理转发工具
- NPS 代理转发工具
- Fpipe 端口转发工具
- ICMP 隧道
- reDuh 隧道
- Lanproxy 代理转发工具
- HTTP 隧道

### 隧道代理怎么完成攻击

典型过程：

```text
攻击者控制一台边界主机或 Web 服务器
-> 上传或运行代理/隧道工具
-> 建立外部攻击端与受害主机之间的通信通道
-> 将攻击者流量转发到内网目标
-> 攻击者扫描、登录或访问内网服务
```

### 隧道代理怎么判断成功

可以判断成功或高度疑似成功的证据包括：

- 主机上出现代理或隧道工具文件
- 出现异常监听端口
- 出现到外部 IP 的长连接
- 出现 Socks、HTTP、DNS、ICMP、UDP 等异常隧道流量
- WebShell 连接后紧跟代理工具访问或流量转发
- 受害主机开始访问大量内网 IP 和端口
- 同一主机既有外联 C2，又有内网扫描或横向连接
- 防火墙或流量日志显示该主机成为中转节点

### 隧道代理可能获得什么

攻击者可能获得：

- 访问内网服务的通道
- 内网资产列表、端口和服务信息
- 内部数据库、OA、运维平台、文件服务入口
- 横向移动条件
- 绕过公网边界访问限制的能力
- 长期隐蔽通信能力

不确定内容：

- 只有代理工具告警，不能确认已经访问了哪些内网资产
- 只有外联连接，不能确认隧道里传输了什么内容
- 没有网络流量明细时，不能确认是否发生数据外传

## 提权类告警怎么看

提权是攻击者从低权限用户获取更高权限的过程。

本批告警中包括：

- Linux 提权工具利用

### 提权怎么完成攻击

典型过程：

```text
获得普通用户权限
-> 收集系统版本、内核版本、sudo 配置、计划任务、SUID 文件等信息
-> 尝试利用漏洞或错误配置提升权限
-> 获得 root 或更高权限
-> 部署持久化、读取敏感文件、控制更多服务
```

### 提权怎么判断成功

可以判断成功或高度疑似成功的证据包括：

- 执行了提权工具或可疑脚本
- 出现内核漏洞利用痕迹
- 普通用户执行后获得 root 权限
- 出现 `/etc/shadow` 等高权限文件访问行为
- 新增高权限账号、sudo 权限或 SSH key
- 修改系统服务、计划任务、自启动项
- 安全软件、日志或审计策略被关闭或修改

### 提权可能获得什么

攻击者可能获得：

- root 或管理员权限
- 全盘文件访问能力
- 系统服务控制能力
- 凭据、Hash、私钥、配置文件
- 安装驱动、后门或持久化组件的能力
- 清理日志和规避检测的能力

不确定内容：

- 只有提权工具利用告警，不能确认提权成功
- 需要结合命令输出、用户权限变化、系统审计和后续行为判断

## 当前这批告警的观察点

从数量看：

- 通用 WebShell 连接数量较高，说明 WebShell 访问或疑似后门连接行为较多
- WebShell 命令执行数量较高，需要重点确认命令内容、进程链和执行账号
- BadTunnel、reGeorg、EarthWorm、Socks5、NPS、SPP 等代理隧道类告警较多，说明存在内网穿透或代理转发风险
- 中国蚁剑、中国菜刀、冰蝎、哥斯拉、weevly 等工具特征明显，需要确认是否为真实 WebShell 管理行为或授权测试
- Linux 提权工具利用需要确认是否提权成功，以及是否产生 root 权限操作
- ICMP、HTTP、UDP 隧道虽然数量少，但具有绕过边界和隐蔽通信意义，应逐条核验

## 一次完整攻击链可能怎么串起来

```text
信息探测
-> 漏洞利用或后台弱口令
-> 文件上传或写入 WebShell
-> WebShell 连接和命令执行
-> 上传代理/隧道工具
-> 建立 Socks5/HTTP/ICMP/UDP 隧道
-> 扫描和访问内网服务
-> 使用提权工具提高权限
-> 部署持久化后门
-> 横向移动和数据窃取
```

这类告警的关键不是单点，而是时间线。

如果同一台主机先出现 WebShell，随后出现代理隧道，再出现内网扫描、登录成功或提权行为，风险会显著升高。

## 安全运营研判方法

### 1. 看入口

确认攻击者最初如何进入：

- 文件上传漏洞
- 命令执行漏洞
- 目录遍历或配置泄露后获得账号
- 后台弱口令
- WebShell 已存在
- 供应链或运维账号泄露

不确定时明确写“不确定”。

### 2. 看 WebShell 文件

关注：

- 文件路径
- 文件名
- 文件后缀
- 创建时间和修改时间
- 文件内容是否混淆或加密
- Web 访问日志中的请求来源
- 是否有同目录其他异常文件

### 3. 看命令执行

关注：

- 执行命令内容
- 父进程和子进程
- 执行账号
- 命令执行时间
- 是否下载文件
- 是否创建账号或写入计划任务
- 是否启动代理、隧道或木马

### 4. 看代理和隧道

关注：

- 工具文件是否落地
- 是否有异常监听端口
- 是否有外部长连接
- 是否有内网扫描行为
- 是否有大量转发流量
- 是否存在 Socks、HTTP、DNS、ICMP、UDP 等隧道特征

### 5. 看权限变化

关注：

- 当前执行账号是否异常
- 是否发生 sudo、root、管理员权限变化
- 是否新增账号
- 是否新增 SSH key
- 是否修改权限组
- 是否访问高权限文件

### 6. 看持久化

关注：

- 计划任务
- 系统服务
- 启动项
- 注册表启动项
- crontab
- SSH authorized_keys
- WebShell 长期存在
- 隐藏文件或伪装文件

## 常见研判结论模板

### WebShell 连接

> 发现目标 Web 资产存在疑似 WebShell 连接行为，攻击者可能通过已落地的后门脚本与服务器交互。当前需确认 WebShell 文件路径、请求来源、请求参数、文件修改时间、Web 服务进程行为及是否存在命令执行、文件读写、代理隧道或木马落地。若确认 WebShell 文件存在并被访问，应按高危入侵事件处置。

### WebShell 命令执行

> 发现目标服务器存在疑似 WebShell 命令执行行为，表现为 Web 请求触发服务端执行系统命令。当前需核验命令内容、执行账号、父子进程、执行结果、文件落地和后续网络连接。若 Web 服务进程启动命令解释器并执行异常命令，可判断为高危控制行为。

### 加密 WebShell 连接

> 发现目标资产存在疑似加密 WebShell 通信行为。该类通信可能通过加密参数隐藏命令内容和返回结果。当前需结合 Web 访问日志、请求体特征、文件样本、解密条件、主机进程和后续行为判断是否真实存在后门连接。

### 隧道代理工具

> 发现目标主机存在疑似代理转发或隧道工具行为，攻击者可能借助该主机访问内网资源或隐藏通信通道。当前需确认工具文件、运行进程、监听端口、外联地址、内网访问记录和流量转发关系。若该主机同时出现 WebShell 或远控行为，应高度怀疑其已被作为内网跳板。

### Linux 提权工具利用

> 发现目标 Linux 主机存在疑似提权工具利用行为。当前需核验执行账号、工具路径、命令参数、系统审计日志、权限变化、新增账号、sudo 配置变更和高权限文件访问记录。仅凭工具利用告警不能确认提权成功，需结合权限变化和后续 root 行为判断。

## 通用研判模板

```text

初始入口：漏洞利用 / 文件上传 / 后台弱口令 / WebShell 已存在 / 未知

攻击行为：连接后门 / 执行命令 / 文件读写 / 建立隧道 / 代理转发 / 提权 / 持久化
是否成功：明确成功 / 高度疑似 / 已拦截 / 仅尝试 / 证据不足

处置建议：隔离主机 / 删除 WebShell / 阻断隧道 / 查杀工具 / 修复入口 / 重置凭据 / 排查横向移动
```

## 一句话研判句式

> 该告警表现为目标资产存在疑似 WebShell 连接、WebShell 命令执行、代理隧道、端口转发或提权工具利用行为，攻击者可能已经获得初始访问权限，并尝试维持后门入口、扩大访问范围、进入内网或提升系统权限。当前需结合 WebShell 文件、请求参数、进程链、命令行、网络连接、权限变化和后续行为判断是否控制成功，以及攻击者是否已获得内网访问通道或高权限能力。

## 当前记录中的不确定内容

- 只有告警名称和数量，不能确认每条告警是否真实成功
- 不能确认 WebShell 文件路径、文件内容和落地方式
- 不能确认 WebShell 命令具体执行了什么
- 不能确认加密 WebShell 通信内容
- 不能确认代理隧道是否已经成功转发内网流量
- 不能确认攻击者访问了哪些内网资产
- 不能确认 Linux 提权是否成功
- 不能确认是否发生数据外传或横向移动
- 不能确认这些工具行为是否属于授权测试
- 需要结合 Web 日志、EDR、主机审计、文件样本、网络流量、认证日志和资产归属进一步判断

## 学习重点

- WebShell 是持久化访问入口，不是普通 Web 请求
- WebShell 命令执行说明攻击者可能已经具备服务器命令执行能力
- 冰蝎、哥斯拉、蚁剑、菜刀、weevly 都属于常见 WebShell 管理工具特征
- reGeorg、EarthWorm、NPS、Socks5、Fpipe 等更偏内网代理和端口转发
- 隧道类告警要看该主机是否成为跳板
- 提权类告警要看权限是否真的变化
- 判断成功必须看文件、命令、进程、网络、权限和后续时间线
- 不确定的地方必须明确标注，不要把“工具特征命中”直接写成“已完全失陷”
