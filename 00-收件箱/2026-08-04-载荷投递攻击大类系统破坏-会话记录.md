## 一句话结论

载荷投递的本质是：攻击者在获得上传、写入、命令执行或远程下载能力后，把 WebShell、恶意文件、可疑脚本或其他攻击工具放入目标系统，并尝试执行或保留这些载荷，为后续命令控制、权限维持、数据窃取、横向移动或系统滥用做准备。

## 总体理解

这批告警主要集中在“载荷投递”。它和前面的信息探测、漏洞利用、命令控制之间的关系可以这样理解：

```text
信息探测
-> 漏洞利用 / 弱口令 / 后台登录 / WebShell 已存在
-> 载荷投递：上传 WebShell、植入可疑文件、上传危险脚本、远程下载恶意文件
-> 执行载荷：命令执行、远控回连、代理隧道、挖矿、数据窃取
-> 权限维持 / 横向移动 / 系统破坏
```

载荷投递不一定等于载荷执行成功，但它说明攻击者已经在尝试把恶意能力放到目标系统上。

## 载荷投递的共同点

共同点可以总结为：

- 攻击者试图把文件、脚本、后门或工具放到目标系统
- 通常依赖文件上传、Web 后台、命令执行、WebShell、远程下载或已有权限
- 投递目标可能是 Web 目录、临时目录、用户目录、系统目录或计划任务路径
- 成功后可能进一步触发命令执行、远控、代理转发、数据窃取或挖矿
- 仅凭告警名称不能确认文件已落地或已执行，需要看文件、进程、日志和网络行为

## 攻击具体行为总结

载荷投递的具体行为可以概括为：

> 攻击者通过上传接口、后台功能、WebShell、命令执行点或远程下载命令，将恶意文件、WebShell、脚本、木马、代理工具、提权工具或挖矿程序写入目标系统，并尝试执行、隐藏或保留这些文件，以获得持续控制或进一步攻击能力。

## 行为分类

| 告警类型 | 具体行为 | 怎么成功 | 可能影响 |
|---|---|---|---|
| 植入可疑文件 | 在目标主机或 Web 目录写入异常文件 | 攻击者拥有上传、写入、命令执行或后台权限 | 后门落地、工具投递、持久化、后续执行 |
| WebShell 后门上传 | 上传 WebShell 脚本到 Web 可访问目录 | 上传校验绕过、后台被控、漏洞写文件或已有权限 | Web 命令执行、文件管理、数据库操作、长期控制 |
| 危险脚本上传 | 上传可执行脚本或高风险脚本文件 | 上传限制不足或攻击者已有文件写入能力 | 执行命令、下载木马、修改系统、横向移动 |
| 远程下载恶意文件 | 目标主机从外部地址下载恶意文件 | 命令执行、WebShell、远控通道或脚本触发下载 | 木马落地、挖矿程序下载、代理工具投递、C2 回连 |

## 植入可疑文件怎么看

“植入可疑文件”说明安全设备发现目标系统出现了可疑文件写入、上传或落地行为。

重点看：

- 文件路径
- 文件名和后缀
- 文件大小
- 文件哈希
- 创建时间和修改时间
- 文件来源 IP 或上传账号
- 文件是否被访问或执行
- 文件是否在 Web 可访问目录
- 文件是否命中威胁情报或恶意规则

可以判断成功的证据：

- 文件真实存在于目标主机
- 文件创建时间与攻击请求时间匹配
- 文件内容具有 WebShell、木马、脚本、代理工具或挖矿特征
- 文件被执行、加载或通过 Web 访问
- 文件落地后出现外联、命令执行或权限维持行为

不确定内容：

- 只有告警名称时，不能确认文件是否真实落地
- 只有上传请求时，不能确认服务器是否保存了文件
- 只有文件落地时，不能确认文件已经执行

## WebShell 后门上传怎么看

WebShell 后门上传是高风险载荷投递行为。攻击者上传 WebShell 后，可以通过 HTTP 请求控制服务器。

典型过程：

```text
发现上传入口或后台入口
-> 绕过文件类型、后缀、内容或路径限制
-> 上传 WebShell 文件
-> 访问 WebShell 地址
-> 执行命令、读写文件、连接数据库或继续投递工具
```

可以判断成功的证据：

- Web 目录存在新增脚本文件
- 该文件能被 HTTP 访问
- 访问后触发命令执行或文件操作
- Web 服务进程启动命令解释器
- 同一源 IP 上传后紧跟访问该文件
- 出现冰蝎、哥斯拉、蚁剑、菜刀等 WebShell 管理工具特征

攻击者可能获得：

- Web 服务账号权限
- Web 目录文件读写能力
- 系统命令执行能力
- 网站源码、配置、数据库连接信息
- 继续上传木马、代理、提权工具的能力

不确定内容：

- 只有上传告警，不能确认 WebShell 可访问
- 只有文件存在，不能确认已经被攻击者连接
- 没有命令执行或访问日志时，不能确认控制成功

## 危险脚本上传怎么看

危险脚本上传通常表示攻击者上传了可执行脚本、自动化攻击脚本、下载执行脚本或系统操作脚本。

常见脚本类型包括：

- Web 脚本：`.php`、`.asp`、`.aspx`、`.jsp`
- Shell 脚本：`.sh`
- Windows 脚本：`.bat`、`.cmd`、`.ps1`、`.vbs`
- Python、Perl、Ruby 等脚本

重点看：

- 脚本是否在可执行路径
- 脚本内容是否包含下载、执行、反连、删除、加密、账号创建等行为
- 脚本是否被解释器执行
- 上传后是否出现新进程、外联或文件变化

可以判断成功的证据：

- 脚本落地且被执行
- 脚本触发下载恶意文件、创建账号、连接外部地址或修改系统
- 脚本执行后出现新文件、新服务、计划任务或异常进程

不确定内容：

- 只有上传行为不能确认脚本执行成功
- 脚本后缀危险不等于内容一定恶意，需要看内容和上下文

## 远程下载恶意文件怎么看

远程下载恶意文件说明目标主机尝试从外部地址拉取可疑文件。

典型过程：

```text
命令执行 / WebShell / 远控通道
-> 执行下载命令或脚本
-> 从外部 URL 下载文件
-> 保存到本地目录
-> 执行文件或作为后续工具使用
```

重点看：

- 下载命令或触发进程
- 下载 URL、域名、IP
- 文件落地路径
- 文件名、哈希、大小
- 是否执行
- 是否产生外联、持久化、挖矿或代理行为

可以判断成功的证据：

- 文件已下载到主机
- 文件哈希命中恶意情报
- 文件被执行或加载
- 下载后出现 C2 回连、反弹 Shell、矿池通信、代理隧道或横向扫描

不确定内容：

- 只有下载请求，不确认下载完成
- 只有恶意 URL，不确认文件落地
- 文件落地不等于执行成功

## 系统破坏：可疑矿池通信

可疑矿池通信说明目标主机可能连接了挖矿矿池，攻击者可能利用受害主机资源进行挖矿。

典型链条：

```text
漏洞利用 / WebShell / 弱口令
-> 远程下载矿工程序或脚本
-> 执行挖矿程序
-> 连接矿池
-> 持续占用 CPU/GPU/网络资源
```

可以判断成功的证据：

- 主机持续连接矿池域名或 IP
- 出现矿工进程或相关文件
- CPU/GPU 使用率异常升高
- 存在下载矿工、执行脚本、创建计划任务或持久化行为
- 同一主机同时出现远程下载恶意文件或危险脚本上传

不确定内容：

- 只有一次矿池连接告警，不能确认挖矿程序稳定运行
- 只有矿池域名命中，不能确认主机已经被控制
- 需要结合进程、文件、资源占用和网络连接判断

## 安全运营研判方法

### 1. 先找文件

关注：

- 是否存在新增文件
- 文件在哪个目录
- 文件是否在 Web 可访问路径
- 文件是否可执行
- 文件哈希是否恶意
- 文件创建时间是否与告警时间一致

### 2. 再看执行

关注：

- 文件是否被执行
- 是哪个进程执行的
- 执行账号是谁
- 命令行参数是什么
- 是否启动子进程
- 是否触发外联或系统变更

### 3. 再看网络

关注：

- 是否连接恶意域名、C2、矿池、下载站点
- 是否存在长连接或周期性通信
- 是否出现代理、隧道、反弹连接
- 是否出现大流量上传或下载

### 4. 最后看时间线

重点看是否形成链条：

```text
WebShell 后门上传
-> WebShell 连接
-> 远程下载恶意文件
-> 植入可疑文件
-> 执行危险脚本
-> C2 回连 / 矿池通信 / 内网代理 / 数据窃取
```

- 不能确认植入可疑文件的具体路径、内容和哈希
- 不能确认 WebShell 后门是否上传成功、是否可访问、是否被连接
- 不能确认危险脚本是否执行成功
- 不能确认远程下载恶意文件是否落地或运行
- 不能确认“小类攻击”具体代表什么攻击类型
- 不能确认“ppp 漏洞测试”对应的漏洞、协议或测试行为
- 不能确认可疑矿池通信是否代表挖矿程序稳定运行
- 需要结合原始规则、请求响应、Web 日志、主机日志、文件样本、进程链、网络流量和资产归属进一步判断

## 学习重点

- 载荷投递关注“攻击者放进了什么”
- 上传成功不等于执行成功，下载成功也不等于运行成功
- WebShell 后门上传一旦落地并可访问，风险很高
- 远程下载恶意文件要追踪下载源、落地路径、哈希和执行行为
- 危险脚本上传要看脚本内容和是否被解释器执行
- 分类语义不清的告警必须标注不确定，不能强行猜测
- 可疑矿池通信要结合进程和资源占用确认是否挖矿
- 判断成功必须依靠证据链：文件、进程、命令、网络、后续行为
