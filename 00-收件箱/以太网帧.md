时钟
**物理层面接收数据一定是离散采样**。信号本身（电平 / 电磁波）是连续模拟信号，但网卡只能**每隔固定瞬间，对信号做一次读取（采样）**，得到一个离散的比特值 0 或 1。

**字段（field）**：帧里一段固定位置、固定用途的字节块。

MAC地址：**48bit，6 字节**，通常写成 12 位十六进制（2^4），冒号分隔，例：`00:1A:2B:3C:4D:5E`。

出厂烧录的 MAC，理论上全球唯一。操作系统、虚拟网卡可更改

MAC 属于**数据链路层（二层）**，作用：**相邻链路节点之间寻址，只在同一个局域网（二层域）生效**。
- 交换机（二层设备）：只读取帧里 MAC，查询 MAC 地址表转发；帧原样转发。
  
- 路由器（三层设备）：收到以太网帧，校验通过后**剥掉二层以太网头部（MAC+FCS），取出里面 IP 包**；
  读取目的 IP 查路由表，得到下一跳 IP → 查 ARP 拿到下一跳 MAC → **用出口网卡 MAC 做源 MAC、下一跳 MAC 做目的 MAC，组装全新以太网帧**



ARP：**同一个局域网内，通过已知 IP，查询对应的 MAC 地址**。
### 触发时机

主机准备发送 IP 数据包，本地 ARP 缓存**缺少对应 IP→MAC 映射**时触发。

- 同网段通信：ARP 查询**目标主机 IP**对应的 MAC；
- 跨网段通信：ARP**只查询网关 IP**对应的 MAC，不会去查远端服务器 MAC。

### 工作流程

1. 主机发 ARP 广播帧（目的 MAC 全 F）：询问 “谁拥有这个 IP，请回复你的 MAC”；
2. 局域网内所有网卡收到广播，IP 匹配的主机回复 ARP 单播，告知自己 MAC；
3. 发送方收到回复，把`IP-MAC`存入 ARP 缓存，缓存有有效期，过期失效；
4. 拿到 MAC 后，主机才可以组装以太网帧发送 IP 包。

# 物理层
把介质信号转换成二进制

#### 电信号


**曼彻斯特编码**
- 不是单纯高 = 1、低 = 0
- **1：中间有一个下降沿（高→低）**
- **0：中间有一个上升沿（低→高）**

原因： 如果长时间连续发一串 1，单纯 NRZ 电平一直不变，接收方时钟会漂移，分不清比特边界。曼彻斯特每个比特中间都有跳变，用来同步时钟。

#### 光信号

光纤
- 有光脉冲 = 1
- 无光脉冲 = 0 （不同标准定义可反过来，协议约定即可
  
#### 无线信号

电磁波

振幅 ASK（调幅）
振幅 = 波形高低。

- 振幅大（波很高）→ 代表 1
- 振幅小（波很矮）→ 代表 0

类比：说话大声 = 1，小声 = 0。

频率 FSK（调频）
频率 = 波形震荡快慢。

- 震荡快（高频）→1
- 震荡慢（低频）→0
  
  WiFi 实际用的是更高级的**正交幅度调制 QAM**：**同时改振幅 + 相位**，一个波形可以携带多个比特（比如同时表达 00、01、10、11），速度更快。相位就是波形起始位置。
# 数据链路层

物理层给二层的是**无限长、没有分隔标记的 01 比特流**，二层靠**前导码 + 帧起始定界符 SFD**，找到帧的开头。

**前导码（Preamble）：** 7 字节，`10101010` 重复 。接收电路检测到每一次信号跳变，就可以**修正自己采样时钟的相位**，把采样点对准每个比特窗口的中间位置

**SFD 帧起始定界符：** 1 字节 `10101011` 最后两位变成`11`。

后面就是以太网帧本体

以太网有两种方式判断帧结束：
帧头部第 3 个字段（目的 MAC + 源 MAC + Type）
网卡把这 2 字节当成一个整数，**看这个整数落在上面哪一个数字区间，就决定怎么解释这个字段**。

0 ≤ 数值 ≤ 1500 → **Length 模式（802.3）**，代表后面载荷有多少字节。这个值表示载荷字节数。以太网规定载荷最大 1500 字节（MTU=1500），所以长度必然≤1500。

1536 ≤ 数值 ≤ 65535 → **Type 模式（Ethernet II）**，代表上层协议类型。协议编号从 1536（0x0600）起步。IPv4 是`0x0800` = 2048，ARP 是`0x0806`=2054，全都大于 1536。

1. **载波消失（现代以太网最常用）**：网线 / 无线信号停止，比特流中断 → 当前帧结束
2. **长度字段（不常用）**：（Length），如果是长度模式，代表后面 Payload 有多少字节。
   
校验：FCS（帧校验序列，帧尾部 4 字节）
发送方： 拿【目的 MAC + 源 MAC + Type/Length + Payload】全部比特，跑 CRC32 算法，算出一个 32bit 数字，放在帧末尾，就是 FCS。

接收方：把【目的 MAC + 源 MAC + Type + Payload】全部做 CRC 计算，算出结果和收到的 FCS 对比。
- 相等：帧没问题，继续上交三层 IP
- 不相等：直接丢弃这个帧，不向上报错（只能**检测错误**，**不能修复错误**。发现错了就丢包）
