## 2. 已经建立的知识体系

### 2.1 告警产生链路

已经形成如下理解：

```text
数据入口
→ 采集
→ 协议解析
→ 流重组
→ 特征匹配
→ 行为分析
→ 威胁情报
→ 白名单过滤
→ 资产标记
→ 告警生成
→ 存储 / 外发
→ 安全运营研判
```

对于 RealEye，可以映射为：

```text
网卡/镜像流量
→ realeye2.0 / Suricata
→ eve.json / flow / http / dns / tls / fileinfo
→ busgo
→ aptgo / scen / assetgo
→ suboss
→ MySQL / ES / ClickHouse
→ syslogsender
→ SIEM / SOC
```

### 2.2 证据价值分层


| 证据层级 | 示例 | 价值 |
|---|---|---|
| 原始证据 | pcap、payload、请求响应、文件样本 | 最强 |
| 结构化检测证据 | eve.json、规则 ID、HTTP/DNS/flow 日志 | 较强 |
| 主机侧证据 | 进程、文件落地、账号登录、命令执行 | 判断成功关键 |
| 情报证据 | IOC、黑名单、DGA、沙箱 | 重要线索 |
| 摘要证据 | syslog、SIEM 聚合字段 | 适合检索，不适合单独定性 |

### 2.3 攻击链视角

已经开始按攻击阶段理解告警：

```text
侦察探测
→ 初始访问
→ 执行
→ 持久化
→ 权限提升
→ 防御绕过
→ 凭据访问
→ 发现
→ 横向移动
→ 收集
→ C2
→ 数据外传
```

告警不再只是“某个名字”，而是要放到攻击链里判断：

- 它是攻击尝试吗？
- 它是初始访问吗？
- 它是否已经进入执行阶段？
- 它是否出现了持久化或横向移动？
- 它是否已经进入数据窃取或 C2 阶段？

### 2.4 防御处置体系

```text
攻击者下一步要做什么
→ 我现在要阻断什么
→ 哪些证据必须先保留
→ 哪些资产可能已经受影响
→ 哪些入口必须修复
```

例如密码爆破成功：

```text
攻击者下一步：登录主机、执行命令、横向移动
防守动作：隔离主机、阻断源 IP、重置账号、查命令、查后门、查横向
```

## 4. 典型研判思路

后续每条告警建议按以下模板研判。

### 4.1 第一步：确认告警是什么

要先问：

```text
告警名称是什么？
攻击类型是什么？
源 IP、目的 IP、端口、协议是什么？
发生时间是什么？
资产是否重要？
```

### 4.2 第二步：确认数据来源

要判断：

```text
它来自原始流量？
来自 HTTP/DNS/flow 日志？
来自 Suricata eve.json？
来自 ecapture？
来自 WAF？
来自 EDR？
来自账号日志？
来自业务日志？
还是来自 SIEM 二次聚合？
```

不同来源决定证据价值。

### 4.3 第三步：确认检测逻辑

要判断：

```text
它是规则命中？
是 IOC 命中？
是行为异常？
是模型判断？
是白名单过滤后仍保留？
是资产重要性提升？
```

### 4.4 第四步：判断攻击阶段

将告警放入攻击链：

```text
扫描探测？
漏洞利用？
凭据爆破？
初始访问？
命令执行？
文件落地？
持久化？
横向移动？
C2？
数据外传？
```

### 4.5 第五步：判断成功程度

按三档判断：

```text
尝试：只有攻击请求或规则命中。
疑似成功：有响应异常、登录成功、可疑文件、异常 SQL、异常命令等迹象。
确认成功：有命令执行、文件落地、C2 外联、后门、横向移动、数据返回等强证据。
```

### 4.6 第六步：找证据缺口

常见缺口：

- 没有响应体
- 没有 pcap
- 没有主机进程
- 没有文件落地记录
- 没有账号登录日志
- 没有数据库审计
- 没有 Web 访问日志
- 没有业务日志

### 4.7 第七步：输出研判结论

推荐输出格式：

```text
告警名称：
攻击阶段：
成功程度：
已确认事实：
不能证明的内容：
证据缺口：
影响资产：
处置建议：
后续排查范围：
```

## 5. 学到能输出什么

当前已经能输出以下类型的内容。

### 5.1 能输出告警解释

可以解释：

```text
这条告警为什么产生？
它依赖什么数据？
它命中了什么逻辑？
它能证明什么？
它不能证明什么？
```

### 5.2 能输出证据链缺口

可以指出：

```text
还缺响应体。
还缺主机进程。
还缺数据库审计。
还缺文件落地记录。
还缺账号登录记录。
还缺业务日志。
```

### 5.3 能输出攻击链阶段判断

可以判断：

```text
这是扫描阶段。
这是初始访问尝试。
这是疑似命令执行。
这是确认失陷后的 C2 外联。
这是横向移动迹象。
```

### 5.4 能输出分级处置建议

可以根据严重程度输出：

```text
尝试：阻断、加固、观察。
疑似成功：保全证据、限制入口、补充日志。
确认成功：隔离、阻断、改密、查后门、查横向、清除恢复。
```

### 5.5 能输出产品能力边界

可以解释：

```text
这个系统主要能看到网络侧证据。
ecapture 增强了 TLS、数据库协议、SSH 命令等可见性。
但它不能默认替代完整 EDR。
syslog 是外发摘要，不是原始证据。
```
