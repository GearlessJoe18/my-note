# 安全告警处置防御措施手册

> 目标：从攻击者视角理解告警后的处置优先级。  
> 核心思路：不要只处理“告警本身”，而是阻断攻击者的下一步。

## 1. 通用处置原则

遇到告警后，先判断它处于攻击链哪个阶段：

```text
探测扫描
→ 漏洞利用 / 密码爆破
→ 初始访问成功
→ 命令执行 / 文件落地
→ 权限维持
→ 横向移动
→ 数据窃取 / 外联 C2
```

处置优先级：

```text
先止血
→ 再阻断
→ 再保全证据
→ 再排查影响范围
→ 再清除后门
→ 最后恢复和加固
```

通用动作：

| 动作 | 目的 |
|---|---|
| 隔离主机 | 防止横向移动、继续外联、继续执行命令 |
| 阻断攻击源 IP / 域名 | 防止攻击者继续投递命令或再次尝试 |
| 禁用或重置账号 | 防止已泄露凭据继续被使用 |
| 保留 pcap、日志、样本 | 防止处置后证据丢失 |
| 查进程、文件、计划任务、服务 | 查找后门和持久化 |
| 排查同源攻击 | 判断是否还有其他主机被打 |
| 修补漏洞和配置 | 防止恢复后再次被入侵 |

重要边界：

```text
告警命中规则，不一定等于攻击成功。
但如果告警已经显示“成功”或存在强成功证据，处置要按失陷主机处理。
```

## 2. 告警严重程度与处置优先级

同一种告警，要按“尝试、疑似成功、确认成功”区分处置强度。

| 严重程度 | 典型含义 | 攻击者可能做到什么 | 处置优先级 | 推荐动作 |
|---|---|---|---|---|
| 尝试 | 只看到攻击请求、扫描、爆破失败、规则命中 | 还在探测或尝试进入 | 中 | 阻断源 IP、加规则、观察同源攻击、补日志确认 |
| 疑似成功 | 出现成功迹象，但证据不完整 | 可能已进入系统或拿到部分结果 | 高 | 限制入口、保全证据、排查主机/账号/文件/进程、扩大检索 |
| 确认成功 | 有登录成功、命令执行、文件落地、数据返回、C2 外联等强证据 | 已具备控制、窃取或横向移动能力 | 最高 | 隔离主机、阻断通信、重置凭据、查后门、查横向、清除恢复 |

判断优先级时，不只看告警名称，还要看证据强度：

```text
攻击请求存在 < 响应异常 < 主机执行痕迹 < 文件落地 < 持久化/横向移动/C2 外联
```

处置强度的原则：

```text
尝试类告警：重点阻断和加固入口。
疑似成功：按高风险事件处理，快速补证据。
确认成功：按失陷事件处理，先隔离再调查。
```

## 3. 密码爆破告警

### 3.1 攻击者视角

密码爆破的目标是拿到可登录凭据。

攻击者成功后，通常会做：

```text
登录主机
→ 执行命令
→ 查看权限
→ 上传工具
→ 建立后门账号或密钥
→ 横向移动
```

### 3.2 如果只是爆破尝试

告警表现：

- 大量登录失败
- 多账号尝试
- 单账号多密码尝试
- 同一源 IP 高频访问 SSH/RDP/数据库/后台登录口

处置措施：

1. 阻断攻击源 IP。
2. 对被爆破账号启用临时锁定或 MFA。
3. 检查是否有登录成功记录。
4. 加强密码策略和失败锁定策略。
5. 检查是否还有其他源 IP 对同一资产爆破。

### 3.3 如果爆破成功

告警意义：

```text
凭据很可能已经泄露，主机存在极高失陷风险。
```

处置措施：

1. **隔离主机**
   防止攻击者继续横向移动或从该主机发起内网探测。

2. **阻断攻击源 IP**
   防止攻击方继续下发命令、重新登录或上传工具。

3. **禁用或重置被爆破账号**
   如果是域账号，要检查该账号是否登录过其他主机。

4. **审查登录记录**
   确认登录时间、来源 IP、登录协议、登录账号、登录成功后的会话时长。

5. **检查命令执行痕迹**
   查 Shell 历史、PowerShell 日志、Windows 事件日志、SSH 命令记录。

6. **检查文件落地**
   重点看临时目录、用户目录、Web 目录、启动目录、下载目录。

7. **检查持久化**
   查新增账号、SSH key、计划任务、服务、自启动项、WebShell、反连程序。

8. **排查横向移动**
   看该主机是否访问了其他内网主机的 SSH、RDP、SMB、WinRM、数据库端口。

9. **恢复前加固**
   改密、启用 MFA、限制登录来源、关闭不必要远程服务。

## 4. SQL 注入告警

### 4.1 攻击者视角

SQL 注入的目标通常是：

```text
判断注入点
→ 获取数据库结构
→ 读取敏感数据
→ 写入 WebShell
→ 提权到系统命令执行
```

### 4.2 如果只是 SQL 注入尝试

告警表现：

- URL 或 POST Body 中出现 `union select`
- 出现 `sleep()`、`benchmark()`、`information_schema`
- 出现 SQL 报错探测语句

处置措施：

1. 阻断攻击源 IP。
2. 在 WAF 或网关增加对应 URI 的防护规则。
3. 检查 HTTP 响应码和响应体，确认是否返回 SQL 报错或敏感数据。
4. 检查同一源 IP 是否持续探测多个参数。
5. 通知业务方排查对应参数是否存在拼接 SQL。

### 4.3 如果疑似注入成功

强成功信号：

- 响应体返回数据库报错。
- 响应体出现大量异常数据。
- ecapture 或数据库审计看到异常 SQL 被执行。
- 数据库日志出现敏感表查询。
- Web 目录出现异常文件。

处置措施：

1. **临时下线或限制漏洞接口**
   防止攻击者继续扩大查询或写入文件。

2. **阻断攻击源 IP**
   防止继续枚举数据库或投递 WebShell。

3. **保留请求、响应、pcap、数据库日志**
   先保全证据，再修复。

4. **检查数据库访问记录**
   重点看敏感表、批量查询、导出行为、异常时间段查询。

5. **检查 Web 目录**
   查是否写入 WebShell、临时脚本、异常上传文件。

6. **轮换数据库账号密码**
   如果数据库凭据可能被读取，必须改密。

7. **修复代码**
   使用参数化查询，禁止字符串拼接 SQL。

8. **排查数据泄露范围**
   确认被查询表、行数、字段和时间范围。

## 5. RCE / 命令执行告警

### 5.1 攻击者视角

RCE 成功后，攻击者通常会：

```text
执行 whoami/id
→ 下载工具
→ 反弹 Shell
→ 建立持久化
→ 内网探测
→ 横向移动
```

### 5.2 如果只是命令执行尝试

告警表现：

- 请求中包含 `cmd=`
- 出现 `whoami`、`id`、`uname`、`ipconfig`
- 出现 `curl/wget/bash/powershell`

处置措施：

1. 阻断攻击源 IP。
2. 检查响应体是否返回命令输出。
3. 检查目标主机是否有外联下载行为。
4. 检查是否有新进程、新文件、新连接。
5. 修复对应漏洞或临时关闭入口。

### 5.3 如果 RCE 成功

强成功信号：

- 响应体出现命令输出。
- ecapture 捕获到异常 Bash/Zsh 命令。
- EDR 或主机日志看到 Web 进程拉起系统命令。
- 主机出现异常外联、下载、反弹 Shell。

处置措施：

1. **立即隔离主机**
   RCE 成功意味着攻击者可能已经获得命令执行能力。

2. **阻断攻击源和外联目的**
   阻断攻击 IP、下载地址、C2 域名和 IP。

3. **保全进程和网络连接证据**
   记录当前进程、端口、连接、登录用户、计划任务。

4. **检查文件落地**
   重点查 `/tmp`、Web 目录、用户目录、启动目录。

5. **查持久化**
   计划任务、服务、自启动、SSH key、新增账号、WebShell。

6. **排查横向移动**
   看是否扫描内网、访问 SMB/RDP/SSH/数据库。

7. **修复漏洞后再恢复上线**
   不要只重启服务，必须修补入口漏洞。

## 6. WebShell 上传 / 文件传输告警

### 6.1 攻击者视角

上传 WebShell 的目标是获得稳定控制入口。

攻击路径：

```text
上传文件
→ 访问文件
→ 执行命令
→ 上传更多工具
→ 持久化和横向移动
```

### 6.2 处置措施

1. 隔离 Web 主机或限制 Web 服务访问。
2. 阻断攻击源 IP。
3. 保留上传请求、文件样本、访问日志。
4. 检查上传目录、临时目录、Web 根目录。
5. 查最近新增或修改的脚本文件。
6. 检查 WebShell 是否被访问和执行命令。
7. 查 Web 进程是否发起异常外联或系统命令。
8. 清除 WebShell 后，修复上传校验、目录权限和解析配置。

## 7. 恶意域名 / C2 外联告警

### 7.1 攻击者视角

C2 外联说明攻击者可能在等待命令或回传数据。

攻击者下一步可能做：

```text
下发命令
→ 上传插件
→ 内网探测
→ 数据打包
→ 数据外传
```

### 7.2 处置措施

1. **隔离外联主机**
   防止继续接收命令或外传数据。

2. **阻断 C2 域名/IP**
   在防火墙、DNS、安全网关阻断。

3. **保留 DNS、HTTP、TLS、flow、pcap**
   确认外联频率、时间、目的、传输大小。

4. **检查主机进程**
   找出哪个进程发起外联。

5. **检查启动项和计划任务**
   C2 通常依赖持久化。

6. **排查同域名同 IP 的其他主机**
   判断是否是批量感染。

7. **查数据外传**
   看是否有大流量上传、压缩包、敏感文件访问。

## 8. 挖矿通信告警

### 8.1 攻击者视角

挖矿攻击的目标是长期占用算力。

常见行为：

```text
漏洞进入
→ 下载矿工
→ 连接矿池
→ 设置自启动
→ 杀安全进程
```

### 8.2 处置措施

1. 隔离主机。
2. 阻断矿池域名/IP。
3. 查高 CPU 进程。
4. 查下载源、矿工文件、钱包地址。
5. 查计划任务、服务、自启动脚本。
6. 查同网段是否还有矿池连接。
7. 清除矿工后修复初始入口漏洞。

## 9. 横向扫描 / 内网探测告警

### 9.1 攻击者视角

内网扫描通常发生在初始失陷之后。

攻击者目标：

```text
发现内网资产
→ 找开放服务
→ 找弱口令
→ 找高价值服务器
→ 横向移动
```

### 9.2 处置措施

1. 优先定位扫描源主机。
2. 隔离扫描源主机。
3. 检查该主机是否刚刚发生登录成功、RCE、WebShell、恶意外联。
4. 阻断异常扫描流量。
5. 排查被扫描资产是否已有登录成功或漏洞利用。
6. 检查扫描工具文件和命令历史。
7. 加强内网访问控制和东西向流量限制。

## 10. 恶意文件 / 沙箱告警

### 10.1 攻击者视角

恶意文件通常用于建立控制、窃密或横向移动。

攻击路径：

```text
下载 / 上传恶意文件
→ 执行
→ 建立连接
→ 持久化
→ 扩散
```

### 10.2 处置措施

1. 隔离涉及主机。
2. 阻断文件下载源和回连地址。
3. 保留文件样本、Hash、传输 pcap。
4. 检查文件是否落地。
5. 检查文件是否执行。
6. 查同 Hash 是否出现在其他主机。
7. 查持久化和外联。
8. 清除文件后修复投递入口。

## 11. 最终输出模板

每次处置后，建议输出：

```text
告警名称：
攻击阶段：
是否成功：
已确认事实：
尚缺证据：
影响资产：
已执行处置：
建议后续动作：
```

示例：

```text
告警名称：SSH 密码爆破成功
攻击阶段：初始访问
是否成功：高概率成功
已确认事实：源 IP 对主机进行爆破，并出现登录成功记录
尚缺证据：登录后命令、文件落地、横向移动情况
影响资产：10.0.0.10
已执行处置：隔离主机、阻断源 IP、重置账号密码
建议后续动作：检查新增账号/SSH key/计划任务/外联连接，排查同账号登录过的其他主机
```
