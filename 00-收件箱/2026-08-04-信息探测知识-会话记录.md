# 信息探测知识学习记录

日期：2026-08-04
主题：信息探测与扫描暴破类告警总结

## 一句话结论

信息探测的本质是：攻击者通过爬虫、端口扫描、目录扫描、敏感文件探测、指纹识别、主机名探测和密码暴破等方式，主动收集目标资产、服务、入口、账号、弱口令、组件版本和暴露面，为后续漏洞利用、登录尝试、横向移动或精准攻击做准备。

## 信息探测是什么

信息探测是攻击链早期非常常见的行为。攻击者通常还没有真正控制系统，而是在回答几个问题：

- 目标有哪些 IP、域名、主机名和端口
- 哪些服务暴露在公网或内网
- 服务是什么类型和版本
- 网站有哪些目录、接口、文件和后台入口
- 是否存在备份文件、配置文件、源码泄露等敏感资源
- 是否存在可登录服务，例如 SSH、FTP、MySQL、SQL Server、Tomcat、phpMyAdmin、SMB、Telnet、LDAP 等
- 是否存在弱口令、默认口令或可爆破账号
- 是否存在后续可以利用的漏洞或攻击路径

信息探测不一定等于入侵成功，但它通常是攻击前置阶段。

## 信息探测和漏洞攻击的区别

信息探测更偏向“发现目标和入口”，漏洞攻击更偏向“利用缺陷造成影响”。

| 类型   | 主要目的                        | 常见结果                  |
| ---- | --------------------------- | --------------------- |
| 信息探测 | 找资产、找端口、找目录、找文件、识别组件、尝试账号口令 | 暴露面被枚举、弱口令被发现、敏感路径被定位 |
| 漏洞攻击 | 利用系统缺陷执行非预期行为               | 越权读取、写入、执行、绕过、控制      |

需要注意：密码暴破既可以归入信息探测，也可以归入攻击行为。因为它不只是“看一看”，而是在尝试获得登录权限。

## 这些告警的共同点

给出的告警包括：

- 网站爬虫
- SSH 密码暴破
- 多端口扫描
- Web 敏感文件探测
- Nmap 扫描
- Web 目录扫描
- nbtstat 扫描
- FTP 密码暴破
- 单端口扫描
- 探测主机名
- MySQL 密码暴破
- 备份文件探测
- SQL Server 密码暴破
- HTTP 密码暴破
- Tomcat 密码暴破
- Masscan 端口扫描
- phpMyAdmin 密码爆破
- SMB 密码暴破
- Telnet 密码暴破
- WhatWeb 指纹识别
- PostgreSQL 数据库密码暴破
- LDAP 密码暴破成功
- webtool 端口扫描

共同点可以总结为：

- 都是在收集目标暴露面或验证可登录入口
- 大多是自动化工具或脚本产生的高频请求
- 很多行为本身不依赖具体漏洞，而是依赖资产暴露、弱口令、默认配置或敏感文件遗留
- 大多数告警只能证明“发生了探测或尝试”，不能直接证明入侵成功
- 判断风险要结合源 IP、目标资产、响应结果、认证日志、失败次数、成功登录、时间线和后续行为
- 它们经常是后续攻击链的前置步骤

## 攻击具体行为总结

信息探测的具体行为可以概括为：

> 攻击者通过自动化工具向目标发送大量请求或连接尝试，枚举网站路径、敏感文件、端口服务、协议响应、组件指纹、主机名和账号口令，试图确认目标有哪些入口、哪些服务开放、哪些资源暴露、哪些账号可用，以及是否存在弱口令或默认配置。

## 行为分类

| 探测类型 | 具体行为 | 关注点 | 可能风险 |
|---|---|---|---|
| 网站爬虫 | 批量访问页面、链接、接口和静态资源 | URL、参数、页面结构、接口入口 | 暴露业务路径、接口和参数 |
| Web 目录扫描 | 枚举常见目录和后台路径 | `/admin`、`/login`、`/backup`、`/upload` 等 | 发现后台、上传点、管理入口 |
| Web 敏感文件探测 | 请求配置、源码、日志、密钥、环境文件 | `.env`、`.git`、`config`、`backup` 等 | 泄露账号、密钥、数据库连接信息 |
| 备份文件探测 | 请求 `.bak`、`.zip`、`.rar`、`.old`、`.swp` 等文件 | 备份包、旧版本文件 | 泄露源码、配置和业务数据 |
| 多端口扫描 | 对同一目标多个端口发起连接 | 开放端口、服务类型 | 发现攻击入口和暴露服务 |
| 单端口扫描 | 对多个目标或单个目标的一个端口探测 | 特定服务是否开放 | 批量寻找可攻击服务 |
| Nmap 扫描 | 使用 Nmap 进行端口、服务、版本或脚本扫描 | 服务版本、协议特征 | 为漏洞匹配提供依据 |
| Masscan 扫描 | 高速大范围端口扫描 | 大范围开放端口 | 互联网暴露面批量发现 |
| nbtstat 扫描 | 探测 NetBIOS 名称和 Windows 网络信息 | 主机名、工作组、共享线索 | 暴露 Windows 网络结构 |
| 探测主机名 | 通过协议、反查或服务响应获取主机名 | 主机命名、环境标识 | 辅助资产识别和横向移动 |
| WhatWeb 指纹识别 | 识别网站框架、CMS、中间件和技术栈 | 组件、版本、插件 | 匹配已知漏洞和默认路径 |
| SSH 密码暴破 | 对 SSH 服务尝试账号密码组合 | 登录失败、成功登录、账号枚举 | 远程登录主机 |
| FTP 密码暴破 | 对 FTP 服务尝试账号密码 | 匿名访问、弱口令 | 文件读取、上传、篡改 |
| HTTP 密码暴破 | 对 Web 登录框或 Basic Auth 尝试密码 | 登录接口、状态码、跳转 | 进入后台或用户系统 |
| Tomcat 密码暴破 | 尝试 Tomcat 管理后台账号口令 | `/manager`、`/host-manager` | 部署恶意应用，进一步执行代码 |
| phpMyAdmin 密码爆破 | 尝试数据库管理后台登录 | 数据库账号、弱口令 | 数据库泄露和篡改 |
| MySQL 密码暴破 | 对 MySQL 服务尝试账号密码 | 3306 暴露、弱口令 | 数据库读取、写入、提权辅助 |
| SQL Server 密码暴破 | 对 SQL Server 服务尝试账号密码 | 1433 暴露、sa 弱口令 | 数据库控制、命令执行风险 |
| PostgreSQL 密码暴破 | 对 PostgreSQL 服务尝试账号密码 | 5432 暴露、弱口令 | 数据库泄露、业务破坏 |
| SMB 密码暴破 | 尝试 SMB 账号密码 | Windows 共享、域账号 | 共享访问、横向移动 |
| Telnet 密码暴破 | 尝试 Telnet 登录 | 明文协议、弱口令 | 设备或主机被登录 |
| LDAP 密码暴破 | 尝试 LDAP 账号密码 | 目录服务账号 | 账号泄露、域内风险 |
| webtool 端口扫描 | 使用特定 Web 工具进行端口探测 | 开放端口和服务 | 暴露面发现 |

## 从告警名称看风险

### 高优先级关注

以下告警需要重点关注，因为它们更接近“获得访问权限”或可能已经成功：

- SSH 密码暴破
- FTP 密码暴破
- MySQL 密码暴破
- SQL Server 密码暴破
- HTTP 密码暴破
- Tomcat 密码暴破
- phpMyAdmin 密码爆破
- SMB 密码暴破
- Telnet 密码暴破
- PostgreSQL 数据库密码暴破
- LDAP 密码暴破成功

特别注意：

- 如果出现“暴破成功”字样，应优先核验认证日志
- 如果同一源 IP 出现大量失败后紧跟一次成功登录，风险较高
- 如果登录成功后出现命令执行、文件上传、异常外联、权限变更，可能已经进入后续攻击阶段

### 中高优先级关注

以下告警主要用于发现攻击入口：

- 多端口扫描
- Nmap 扫描
- Masscan 端口扫描
- Web 敏感文件探测
- Web 目录扫描
- 备份文件探测
- WhatWeb 指纹识别

这些行为本身不一定成功，但如果命中敏感文件、后台入口、管理端口或老旧组件，风险会上升。

### 辅助研判类

以下行为通常用于补充资产信息：

- 网站爬虫
- nbtstat 扫描
- 探测主机名
- 单端口扫描
- webtool 端口扫描

它们可能是大规模自动化扫描的一部分，也可能是攻击者在绘制目标资产地图。

## 安全运营看信息探测告警的方法

### 1. 看源 IP

关注：

- 是否来自公网
- 是否来自已知扫描器、云主机、代理、境外地址
- 是否是内部安全扫描器
- 是否短时间访问多个资产
- 是否来自同一源 IP 的多种探测行为

不确定项：

- 仅凭源 IP 不能确认攻击者身份
- 云主机和代理 IP 只能说明来源基础设施，不等于真实攻击者

### 2. 看目标资产

关注：

- 是否是公网资产
- 是否是核心系统、数据库、VPN、堡垒机、OA、运维平台
- 是否暴露了管理端口
- 是否属于应当只在内网访问的服务

### 3. 看端口和协议

常见高风险端口包括：

- SSH：22
- FTP：21
- Telnet：23
- SMB：445
- MySQL：3306
- SQL Server：1433
- PostgreSQL：5432
- Redis：6379
- Elasticsearch：9200
- Tomcat / Web 管理端：8080、8009、8443 等
- RDP：3389

端口本身不是漏洞，但不必要的暴露会扩大攻击面。

### 4. 看请求路径和文件名

Web 探测重点看是否访问：

- 后台路径：`/admin`、`/manager`、`/login`、`/console`
- 配置文件：`.env`、`config.php`、`application.yml`、`web.config`
- 源码目录：`.git/`、`.svn/`
- 备份文件：`.bak`、`.zip`、`.rar`、`.old`、`.tar.gz`
- 日志文件：`.log`
- 数据库文件：`.sql`、`.db`
- 上传目录：`/upload`、`/uploads`

### 5. 看认证结果

密码暴破类告警必须结合认证日志判断：

- 失败次数
- 是否出现成功登录
- 成功登录的账号
- 成功登录的源 IP
- 是否存在同一账号被多源尝试
- 是否存在同一源 IP 尝试多账号
- 成功登录后的操作行为

### 6. 看时间线

单个探测告警价值有限，要看是否形成链条：

```text
端口扫描 -> 指纹识别 -> 目录扫描 -> 敏感文件探测 -> 密码暴破 -> 登录成功 -> 文件上传/命令执行/异常外联
```

如果出现连续链条，风险明显升高。

## 常见研判结论模板

### 端口扫描

> 发现源 IP 对目标资产发起端口扫描行为，尝试枚举开放端口和服务暴露情况。当前告警可判断存在资产探测行为，是否造成实际影响需结合目标端口开放情况、服务版本、后续访问路径和漏洞利用告警进一步确认。

### Web 目录扫描

> 发现源 IP 对目标 Web 站点发起目录枚举请求，访问多个常见后台路径、敏感目录或默认文件。当前可判断存在 Web 暴露面探测行为，是否命中有效路径需结合响应状态码、响应内容和 Web 访问日志确认。

### 敏感文件探测

> 发现源 IP 请求目标站点的敏感文件或备份文件路径，疑似尝试获取配置、源码、日志、备份包或密钥信息。当前需确认响应是否返回 200、文件大小是否异常、响应内容是否包含敏感信息，不能仅凭请求判断泄露成功。

### 密码暴破

> 发现源 IP 对目标服务发起多次账号密码尝试，疑似密码暴破行为。当前需结合认证日志确认失败次数、是否存在成功登录、登录账号、登录后行为及是否触发账号锁定策略。若存在成功登录或登录后异常操作，应按高危事件处置。

### 指纹识别

> 发现源 IP 对目标 Web 服务进行指纹识别，尝试获取网站框架、CMS、中间件、组件版本或服务特征。该行为通常用于后续漏洞匹配和精准攻击，是否存在实际风险需结合识别到的组件版本和后续攻击行为判断。

## 示例：SSH 密码暴破告警怎么看

重点字段：

- 源 IP
- 目标 IP
- 目标端口 22
- 尝试账号
- 失败次数
- 是否成功登录
- 时间范围
- 登录后是否执行命令

判断：

- 只有大量失败：可判断为暴破尝试
- 大量失败后成功：高风险，需要确认账号是否被攻破
- 成功后出现异常命令、外联、下载文件、创建账号：可能已被入侵
- 如果源 IP 是内部扫描器或堡垒机：需要确认是否为授权测试或正常运维行为

不确定内容：

- 没有认证日志时，不能确认是否登录成功
- 没有主机日志时，不能确认登录后做了什么
- 没有资产归属时，不能判断业务影响范围

## 示例：Web 敏感文件探测怎么看

重点字段：

- 请求路径
- 响应状态码
- 响应长度
- 响应内容类型
- 是否返回敏感关键字
- 是否存在下载行为

判断：

- 请求 `.env`、`.git/config`、`backup.zip` 等路径，说明存在敏感文件探测
- 如果返回 404 或被 WAF 拦截，通常是探测失败
- 如果返回 200 且响应长度明显大于普通错误页，需要进一步核验
- 如果响应内容包含数据库密码、密钥、Token、源码或配置，说明可能发生信息泄露

不确定内容：

- 仅有请求包，不能确认文件存在
- 仅有 200 状态码，不能确认是敏感内容，也可能是统一错误页
- 需要结合响应正文或文件下载日志判断

## 当前这批告警的观察点

从数量看，网站爬虫、SSH 密码暴破、多端口扫描数量非常高，说明环境中存在大量自动化探测和登录尝试。

需要重点关注：

- SSH 密码暴破数量很高，需确认是否有成功登录
- 多端口扫描数量很高，需确认是否来自授权扫描源
- Web 敏感文件探测和 Web 目录扫描较多，需确认是否命中真实文件或后台路径
- Nmap、Masscan、WhatWeb 等工具特征说明存在自动化资产识别行为
- 数据库、Tomcat、phpMyAdmin、SMB、Telnet、LDAP 等暴破类告警需要结合认证日志核验

不确定内容：

- 只有告警名称和数量，无法确认攻击是否成功
- 无法确认源 IP 是否为授权扫描器
- 无法确认目标资产是否真实暴露高危服务
- 无法确认是否存在账号登录成功，除非有认证日志或告警原始证据
- “LDAP 密码暴破成功”从告警名称看风险较高，但仍应以认证日志和安全设备原始证据为准

## 通用研判模板

```text
探测入口：IP / 端口 / URL / 目录 / 文件 / 登录接口 / 协议服务
探测方式：爬虫 / 端口扫描 / 目录扫描 / 敏感文件探测 / 指纹识别 / 密码暴破
攻击目标：发现资产 / 识别服务 / 枚举路径 / 获取敏感文件 / 验证账号密码 / 匹配漏洞
当前证据：告警名称 / 请求包 / 响应包 / 认证日志 / Web 日志 / 防火墙日志 / 主机日志
是否成功：明确成功 / 明确失败 / 已拦截 / 仅探测尝试 / 证据不足
后续行为：漏洞利用 / 成功登录 / 文件上传 / 命令执行 / 横向移动 / 异常外联
不确定项：缺少响应内容、缺少认证日志、缺少源 IP 归属、缺少资产暴露面信息等
```

## 一句话研判句式

> 该告警表现为攻击者或自动化工具对目标资产进行信息探测，通过爬虫、端口扫描、目录枚举、敏感文件请求、指纹识别或账号密码尝试等方式收集服务暴露面和可用入口。当前只能确认存在探测或暴破尝试，是否命中有效资源、是否登录成功或是否进入后续攻击阶段，需要结合响应内容、认证日志、资产归属、WAF/防火墙动作和主机日志进一步确认。

## 学习重点

- 信息探测是攻击链前置阶段，不一定代表入侵成功
- 密码暴破比普通扫描风险更高，因为它直接尝试获得访问权限
- 扫描工具特征可以帮助识别自动化行为，但不能单独判断成功
- 判断敏感文件探测是否成功，要看响应状态码、响应长度和响应内容
- 判断密码暴破是否成功，要看认证日志和登录后行为
- 判断端口扫描风险，要看目标端口是否开放、服务是否必要、是否暴露公网
- 看到“成功”类告警要优先核验原始日志
- 不确定的地方要明确写“不确定”，不要把尝试当成成功
