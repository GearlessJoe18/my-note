# RealEye NDR 系统核心能力边界

> 目标：只保留这套系统最重要的能力边界，方便后续学习告警时快速判断“它能看到什么、能证明什么、不能证明什么”。

## 1. 总体结论

这套系统不是单纯的“只看镜像流量”的传统 NDR。

更准确的定位是：

```text
NDR 为核心
+ Suricata 协议解析与规则检测
+ ecapture/eBPF 增强采集
+ APT/IOC/沙箱/DGA 情报检测
+ 资产上下文
+ suboss 告警过滤与资产标记
+ syslogsender 告警外发
```

但它也不能直接等同于 EDR。

当前资料没有明确看到完整 EDR 常见能力，例如：

- 进程树
- 父子进程链
- 文件落地
- 注册表变更
- 服务/计划任务创建
- 主机隔离和查杀

所以研判时要记住：

```text
它比纯 NDR 可见性更强，但不能默认具备完整 EDR 证据。
```

## 2. 原本 NDR 能力

核心入口：

```text
网卡/镜像流量
→ realeye2.0 / Suricata
→ 协议解析
→ 流重组
→ 规则匹配
→ eve.json / alert / flow / http / dns / tls / fileinfo
```

主要能力：

| 能力 | 能看到什么 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 原始流量检测 | 五元组、协议、payload | 网络通信真实发生 | 主机已被入侵 |
| HTTP 检测 | URI、Header、Body、Host、UA | 请求中存在攻击特征 | 攻击一定成功 |
| DNS 检测 | 查询域名、响应 IP | 主机查询过某域名 | 主机一定连上 C2 |
| TLS 元数据 | SNI、证书、流量特征 | 有加密通信及证书特征 | 加密内容是什么 |
| 文件提取 | 传输文件、Hash、文件类型 | 网络上传输过文件 | 文件已落地或执行 |
| Suricata 规则 | sid、规则名、命中字段 | 满足规则条件 | 漏洞利用成功 |
| flow 记录 | 源/目的 IP、端口、协议、字节数 | 两端存在会话 | 会话内容一定恶意 |


## 3. ecapture 增强能力

资料中明确看到 `ecapture` 是 eBPF 抓包/捕获引擎。

它不是传统旁路 NDR，而是增强了部分主机侧网络与协议可见性。

### 3.1 TLS/SSL 解密

资料描述：

```text
通过 eBPF 钩子捕获 OpenSSL/BoringSSL 会话密钥，解密后输出明文流量。
```

开发版资料还提到：

```text
解密后的明文送到分析引擎。
```

能力价值：

- HTTPS 不再只能看 SNI/证书。
- 可能还原出 HTTP 明文请求。
- 对加密 Web 攻击、加密下载、加密 C2 有帮助。

能力边界：

- 依赖部署位置和 Hook 能否覆盖对应 TLS 库。
- 不代表所有 HTTPS 都能解密。
- QUIC、未覆盖 TLS 库、硬件卸载等可能看不到明文。

### 3.2 MySQL/PostgreSQL 协议解析


```text
捕获数据库协议的 SQL 语句和执行结果，用于 SQL 注入分析。
Web 应用或客户端已经向数据库发送 SQL
→ ecapture 捕获这段数据库通信
→ 解析出 SQL 语句和数据库响应
```

能力价值：

- HTTP 层只能看到“攻击者发了疑似 SQL 注入请求”。
- 数据库协议层可以进一步看到“后端数据库实际收到了什么 SQL”。
- 如果看到异常 SQL 和执行结果，能更接近判断 SQL 注入是否进入后端执行路径。

能力边界：

- 看到 SQL 不等于 SQL 注入成功。
- 还要看 SQL 来源、执行结果、返回数据、业务日志。
- 资料未完全说明这些 SQL 捕获结果是否一定进入统一 `eve.json/busgo/suboss` 告警链路，真实研判要看具体字段。

### 3.3 Bash/Zsh 命令捕获

```text
捕获通过 SSH 执行的远程命令，用于行为审计和异常检测。
```

能力价值：

- 能看到部分 SSH 会话中的远程命令。
- 对 RCE 后续行为、远程运维审计、异常命令识别有价值。

能力边界：

- 看到命令不等于一定是攻击者执行。
- 需要确认主机、账号、来源 IP、时间线、执行结果。
- 它不是完整 EDR 进程树，不能天然还原父子进程链。

## 4. APT/情报能力

相关模块：

```text
apt / aptgo
```

主要能力：

| 能力 | 说明 | 边界 |
|---|---|---|
| 恶意域名检测 | DNS/HTTP 中域名命中黑名单或 APT 情报 | 命中情报不等于主机失陷 |
| 黑 IP 检测 | 通信 IP 命中黑名单 | 可能是误报、代理、扫描、过期情报 |
| DGA 检测 | 识别疑似随机生成域名 | 模型判断，需要上下文确认 |
| 文件扫描 | 文件提取后做 AV/恶意检测 | 文件恶意不等于目标已执行 |
| 沙箱联动 | 可疑文件送沙箱分析 | 沙箱恶意不等于真实环境执行成功 |
| IOC 关联 | IP、域名、Hash 关联 | IOC 是线索，不是最终结论 |

## 5. 资产与告警治理能力

相关模块：

```text
assetopt / assetgo / suboss
```

### 5.1 资产上下文

能补充：

- 资产 IP
- 端口服务
- 证书信息
- User-Agent
- 操作系统或服务指纹
- 源/目的是否属于已知资产

资产标记：

| 标记 | 含义 |
---|---|
| `ASSET_NO` | 两端都不是已知资产 |
| `ASSET_SRC` | 源 IP 是已知资产 |
| `ASSET_DST` | 目的 IP 是已知资产 |
| `ASSET_DOUBLE` | 两端都是已知资产 |

边界：

```text
资产标记用于判断优先级，不是攻击成功证据。
```

### 5.2 suboss 告警治理

核心流程：

```text
安全事件 JSON
→ /vdata/run/
→ ReadRunFileThread
→ MySQL alert 表
→ AlertMatch
→ 规则匹配 / 白名单过滤 / 资产标记
```

白名单类型：

- 源 IP
- 目的 IP
- 源/目的 IP 组合
- 域名
- URL
- 时间段白名单

边界：

```text
suboss 可以降低误报、补资产上下文，但不能把“命中规则”变成“攻击成功”。
```


## 6. 最重要的能力边界

### 6.1 这套系统能证明

- 某段网络通信发生过。
- 某个协议字段或 payload 被观察到。
- 某条规则或情报被命中。
- 某个文件在网络中传输过。
- 某个域名/IP/Hash 有威胁情报关联。
- 某条告警经过白名单过滤后仍保留。
- 某些场景下，ecapture 可能看到 TLS 明文、数据库 SQL、SSH 远程命令。

### 7.2 这套系统不能单独证明

- 主机已经被入侵。
- 漏洞利用已经成功。
- WebShell 已经落地执行。
- 恶意文件已经运行。
- 账号已经被盗用。
- 数据已经泄露。
- 攻击者已经完成横向移动。
- 攻击者已经完成持久化。
