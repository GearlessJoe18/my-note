# 前端开发知识库重构设计

- 日期：2026-07-28
- 状态：待用户审阅
- 目标：为刚进入行业的前端开发者建立一套以系统知识结构为主、日常工作查阅为辅的 Obsidian 知识库。

## 1. 设计原则

1. **技术知识为主干**：按可迁移的技术领域组织，而非按来源、课程或一次性问题堆放。
2. **实践与原理分离、链接相连**：项目复盘记录业务上下文；原理笔记记录可复用的概念。复盘中应链接到对应原理。
3. **低摩擦输入**：未分类的新内容先进入收件箱；每日记录先保留，再逐步沉淀为正式知识笔记。
4. **中文语义命名**：文件名表达主题，便于全局搜索；不保留无含义的 `01`、`未命名` 等名称。
5. **少层级、强入口**：目录最多四层；索引页（MOC）是知识浏览与学习的入口。
6. **迁移不丢失信息**：现有正文全部保留。迁移仅改变路径、必要的标题与文件名，并修复受影响的内部链接。

## 4. 命名和链接规则

- 文件名使用完整语义：`01.md` 改为如 `npm-run-脚本命令.md`；`未命名.md` 根据正文命名，空白文件移入归档。
- 笔记标题与文件名保持一致；仅在标题更适合阅读时可省略技术前缀。
- 每次移动或重命名后检查并修复 `[[Wiki 链接]]` 与嵌入链接；不修改无关的外部链接或代码示例。
- 新建概念笔记使用同一术语，避免同时存在“Promise”“promise”“承诺对象”等同义文件。
- 图片和其他非 Markdown 资源放入 `90-资源与附件/图片/`，在正文中以 `![[文件名]]` 引用。

## 6. 导航页职责

- **前端知识地图**：按基础、Vue、Node、工程化、实践、职业发展列出主题入口；每个主题可标记“未开始 / 学习中 / 可工作使用 / 需复习”。
- **当前学习路线**：依次维护“基础夯实 → Vue 2 项目维护 → Vue 3 + TypeScript → 工程化 → Node.js → React 入门”的下一步行动和关联笔记。
- **工作问题索引**：以登录认证、路由、缓存、构建、接口与错误排查等工作场景，链接到对应复盘与知识笔记。

## 7. 执行与验收

1. 创建目录与三份导航页。
2. 按第 3 节移动、重命名现有 Markdown 和附件；保留原正文。
3. 处理空白或未命名内容：有正文的笔记按主题重命名，空白笔记放入归档。
4. 创建必要的索引链接，至少覆盖现有技术主干与工作复盘。
5. 扫描全 vault 的 Wiki 链接，修复因移动/重命名产生的断链。
6. 复查：根目录只保留 vault 配置与必要项目元文件；`00-收件箱` 初始为空；不删除用户已有内容。

## 8. 非目标

- 本次不重写现有所有技术笔记的正文，也不补写缺失的知识内容。
- 本次不改变 `.obsidian/` 或 `.claudian/` 的配置。
- React 仅在学习路线中预留入口；尚未开始学习时不创建大量空目录或笔记。
